# Starship 多租户架构设计方案

## 1. 设计目标

Starship 未来支持：

-   SaaS 平台
-   多企业管理系统
-   行业云平台

因此需要提前规划 Tenant 体系。

目标：

-   一个系统服务多个企业
-   企业数据隔离
-   用户权限隔离
-   模块能力复用
-   支持未来 SaaS 商业模式

核心原则：

    租户负责边界

    权限负责访问

    Module负责业务

    Core负责规则

------------------------------------------------------------------------

# 2. 多租户模式选择

常见三种模式：

## 模式一：独立数据库

    Tenant A

    Database A


    Tenant B

    Database B

优点：

-   隔离最高
-   安全性好

缺点：

-   运维成本高

适合：

大型客户。

------------------------------------------------------------------------

## 模式二：共享数据库 + tenant_id

    sa_orders

    id

    tenant_id

    user_id

    amount

优点：

-   简单
-   成本低

缺点：

-   需要严格数据隔离

适合：

SaaS 初期。

------------------------------------------------------------------------

## 模式三：混合模式

默认：

共享数据库。

高级客户：

独立数据库。

推荐：

Starship采用混合模式。

------------------------------------------------------------------------

# 6. 数据隔离方案

推荐：

Model自动增加：

    tenant_id

例如：

订单：

``` sql
sa_orders

id

tenant_id

user_id

amount
```

查询：

自动：

``` sql
where tenant_id = 当前租户
```

------------------------------------------------------------------------

# 7. TenantResolver设计

Core提供：

``` php
interface TenantResolverInterface
{

public function current();

public function id();

}
```

负责：

获取当前请求租户。

来源：

-   Header
-   Token
-   Domain

------------------------------------------------------------------------

# 8. 多租户中间件

流程：

    Request

    ↓

    TenantMiddleware

    ↓

    解析租户

    ↓

    绑定TenantContext

    ↓

    业务执行

------------------------------------------------------------------------

# 9. Module适配规范

Module不能：

直接：

``` php
Tenant::id()
```

应该：

依赖：

``` php
TenantResolverInterface
```

例如：

Shop：

    OrderService

    ↓

    TenantResolver

    ↓

    创建订单

------------------------------------------------------------------------

# 10. 权限与租户结合

权限模型：

    Tenant

    ↓

    User

    ↓

    Role

    ↓

    Permission

例如：

A企业：

    管理员

    拥有：

    shop.order.*

B企业：

    员工

    只有：

    shop.order.view

------------------------------------------------------------------------

# 11. Module启用范围

未来支持：

平台级：

    Shop Module

租户级：

    Tenant A 启用商城

    Tenant B 不启用

增加：

    tenant_modules

    tenant_id

    module

    status

------------------------------------------------------------------------

# 12. Plugin配置隔离

插件配置不能全局共享。

错误：

    payment_wechat

    appid

应该：

    tenant_id

    plugin

    key

    value

例如：

A公司：

自己的微信商户号。

------------------------------------------------------------------------

# 13. Event与租户

事件必须携带Tenant。

例如：

``` php
OrderCreatedEvent
```

包含：

    tenant_id

    order_id

避免跨租户。

------------------------------------------------------------------------

# 16. 开发阶段建议

## 当前阶段

不要强制所有模块多租户。

先预留：

-   tenant_id字段
-   TenantResolver接口
-   Context机制

## SaaS阶段

再开启：

-   Tenant Module
-   数据隔离
-   套餐系统
